	2. Management Approach
2.1 Project Process
  

Figure 1 – Proposed project process for SmartLibrary
This project was developed using the Scrum model, which is part of the Agile methodology, for the following reasons:
●       The initial planning and documentation help keep both large and dynamic teams aligned, ensuring everyone works toward a shared objective.
●       Scrum provides a structured and disciplined approach to project management.
●       It is straightforward to understand, making task organization and tracking easy to manage.
●       The model supports flexibility, allowing for the seamless integration of design or specification changes early in the process.
●       Milestones and deadlines are clearly defined, ensuring timely delivery.
●       The framework emphasizes both in-person and virtual meetings to maintain effective communication.
●       Scrum fosters collaboration among team members, encouraging them to jointly define and refine solutions.

6. Configuration Management
6.1 Document Management
To manage and archive all project documents and related information, the team uses Google Drive 
● Google Drive: All project documents are stored in the shared project drive. Any addition or modification must be updated and versioned properly within the documents.


6.2 Source Code Management
Version Control System: Git is used for version control, with GitHub as the platform to store and manage the source code.


Branching Strategy:
* Main: Contains stable, production-ready code.
* Dev: Used for ongoing feature development and integration.
* Member’s branch: Individual branches for each team member.
* Hotfix Branches: Created for urgent fixes that need to be applied directly to production.


Commit and Pull Request Practices:
* Make frequent commits with clear and meaningful messages (e.g., [Add], [Doc], [Fix], [Update]).
* All changes must go through Pull Requests (PRs) and code review before being merged into the main branch.
* Code reviews are conducted to maintain code quality and detect issues early.


Automated Testing and CI:
* Continuous Integration (CI) tools are used to automate the build and testing process.
* Automated tests are executed on every commit to ensure system stability.


Code Documentation:
*  Proper documentation is maintained for every function, class, and module.
*  A Change Log is kept to track significant changes and version history.


Backup and Recovery:
*  Regular backups are performed to prevent data loss.
*  A complete version history is maintained to allow rollback when necessary.
