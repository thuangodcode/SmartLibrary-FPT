2. User Requirements
2.1 Actors
[An actor is a person (or sometimes another software system or a hardware device) that interacts with the system to perform a use case. Following are some questions you might ask to help user representatives identify actors
* Who (or what) is notified when something occurs within the system?
* Who (or what) provides information or services to the system?
* Who (or what) helps the system respond to and complete a task?
This part gives the description of system actors, you can follow the table form as below]
#
	Actor
	Description
	1
	Administrator
	The person responsible for system-level administration. Administrators log in to manage Librarian accounts, Reader accounts and account status, and user roles and access. They create and update borrowing policies and library regulations, configure AI providers and services (including testing connections and synchronizing the RAG index), browse the collection overview, and view, review, and export reports and statistics. 
	2
	Librarian 
	The library staff member who handles daily operations. Librarians review Reader registrations, manage books, categories, book copies, and inventory, and process borrowing, returns, reservations, and renewals. They monitor overdue loans, record fines and process payments (cash and PayOS), handle lost and damaged book cases, respond to Reader support requests, publish library news and notices, and use AI-assisted acquisition suggestions and insights to support their decisions. 
	3
	Reader 
	The library user, such as a student or lecturer, who uses the library services. Readers register, log in, and manage their profile. They search and browse books, manage favorites, submit borrowing, reservation, and renewal requests, track loans and due dates, and view and pay fines online via PayOS. They also rate and review books, send support requests, receive notifications, and use AI book recommendations and natural-language search. 
	4
	AI Services 
	A system actor (software component) that provides intelligent features. It supplies personalized book recommendations, semantic search of library books and policy documents (RAG), advisory acquisition suggestions, operational insights, and overdue status indicators. Its outputs only support users; final decisions remain with Librarians.  
	5
	PayOS Payment Gateway 
	An external payment system that processes online fine payments initiated by Readers (and PayOS-supported payments handled by Librarians) and returns the payment result to SmartLibrary.

3.2.4 Verify Personal Documents
● Function Description:
Users must upload personal identification documents to verify their identity during account registration. The system supports Citizen ID Card (CCCD/CMND), Student ID Card, and Driving License. Users can upload images of the front and back of the selected document. An optional selfie holding the document can also be provided. After submission, the registration request is sent for administrative approval.
● Function Activation:
When a user registers a new account, the registration process displays the personal document verification interface after the user has completed the information and email OTP verification steps.
❖ Selecting the Document Type:
* Button/Navigation: The document type options are displayed as CCCD/CMND, Student ID Card, and Driving License.
* Activation: The user selects one of the available document types.
* Function: The system identifies the type of document the user intends to submit for identity verification.
❖ Uploading the Front and Back of the Document:
* Button/Navigation: Two upload areas are displayed: “Front Side” and “Back Side”.
* Activation: The user clicks an upload area to take a photo or upload an image from their device.
* Function: The system accepts document images in JPEG or PNG format, with a maximum file size of 5 MB per image. Both the front and back images are required.
❖ Uploading a Selfie Holding the Document (Optional):
* Button/Navigation: An optional upload area labeled “Selfie Holding the Document” is displayed below the document image fields.
* Activation: The user clicks the upload area to take a photo or upload an image.
* Function: The system accepts an optional selfie image in JPEG or PNG format, with a maximum file size of 5 MB.
❖ Submitting Documents for Approval:
* Button/Navigation: The user proceeds using the submission or continuation button provided at the bottom of the registration interface.
* Activation: The user submits the required document images after completing the form.
* Function: The system receives the submitted documents and sends the registration request for administrative approval. The registration process then moves to the “Pending Approval” stage.
❖ Navigating Back to Login:
* Button/Navigation: A “Back to Login” option is available if provided by the interface.
* Activation: The user clicks the option.
* Function: The system redirects the user to the login page.


  



3.2.5 HomePage
● Function Description:
The Home Page provides users, including guests and logged-in users, with an overview of the SmartLibrary system. It displays the main navigation menu, a book search bar, notifications, user account information, and featured library content. Users can search for books, browse book categories, explore books, view library news, and access library-related services.
● Function Trigger:
When users access the SmartLibrary web application, the Home Page is displayed. The interface provides the following functions:
❖ Searching for Books:
* Button/Navigation: A search input field and a “Search Library” button are displayed in the header.
* Trigger: The user enters a book title, author, ISBN, or other search keywords and clicks the “Search Library” button.
* Function: The system processes the search query and displays relevant library books.
❖ Browsing Book Categories:
* Button/Navigation: A “Categories” menu is displayed in the navigation bar.
* Trigger: The user clicks the “Categories” menu.
* Function: The system displays available book categories, allowing users to browse books by category.
❖ Exploring Books:
* Button/Navigation: A “Discover Books” item is displayed in the navigation bar.
* Trigger: The user clicks “Discover Books”.
* Function: The system navigates the user to the book discovery section, where available books can be explored.
❖ Viewing Library News:
* Button/Navigation: A “News” item is displayed in the navigation bar.
* Trigger: The user clicks “News”.
* Function: The system navigates the user to the library news section to view published news and announcements.
❖ Accessing Library Services:

4. Non-Functional Requirements
4.1 External Interfaces
1. User Interfaces
Responsive Web Design: The system must deliver a fully responsive web interface supporting modern desktop, tablet, and mobile browsers (Google Chrome, Mozilla Firefox, Microsoft Edge, Safari).
Consistent Design System: Built on React 19 with a standardized typography, harmonious color palette (FPT University Orange #F36F21, Library Deep Forest Green #244D39, and clean neutral tones), and Lucide React icons.
Clarity & Intuitiveness: Forms, action buttons, status pills (e.g., Available, Borrowed, Overdue, Pinned), and book catalog cards must have clear, readable Vietnamese labels with high-contrast ratios.
Real-time Feedback: Key actions must provide immediate visual indicators (loading spinners, progress bars, and modal confirmation dialogs) to prevent duplicate submissions.
2. Payment Integration
Vietnamese Payment Gateways: Must integrate with popular domestic payment solutions (e.g., VNPay, MoMo, VietQR bank transfer) to enable online fine payments for overdue books, lost item compensations, or library membership services.
Transaction Verification & Webhook: Must support asynchronous payment callbacks/webhooks with HMAC-SHA256 signature validation to automatically update reader balance, clear outstanding fines, and issue digital receipts.
Local Financial Compliance: Maintain transaction references and payment histories compliant with Vietnamese electronic transaction regulations.
3. External Systems
Cloud Database & Auth (Supabase PostgreSQL): Must securely communicate with Supabase via an IPv4 Session Pooler with TLS encryption for relational data persistence and role-based authentication.
Cloud Media Storage (Cloudinary): Integration with Cloudinary CDN for secure, optimized upload, storage, and retrieval of book cover images, category thumbnails, reader identification cards, and news announcement banners.
Artificial Intelligence Engine (Google Gemini API): Secure API connection with Google Gemini (Embedding text-embedding-004 and Gemini Flash models) via HTTPS for Semantic Search (RAG) and intelligent book recommendations.
Realtime Communication (ASP.NET Core SignalR): WebSocket-based real-time hub (/hubs/support-chat, /hubs/circulation) for instant reader support chat, immediate book checkout notifications, and real-time news broadcast.
Mailing Services (SMTP / Brevo / Resend): Integration with transactional email gateways to deliver verification OTPs, account activation notices, and automatic overdue reminder emails.
4.2 Quality Attributes
4.2.1 Usability 
User-Friendly Interface: The system layout must be self-explanatory. University students and librarians should be able to navigate the book catalog, borrow/return books, and manage inventory within 30 minutes of orientation.
Design Standards & Accessibility: Adhere to modern UI principles (Material Design & Shadcn UI inspirations) with clear semantic HTML5, keyboard navigation support, and ARIA labels.
Simple Operational Flows:
Placing a book reservation or renewal must be achievable in under 3 clicks.
Direct book checkout by librarian must be executed in under 4 steps (Scan Reader ID  Scan Book Barcode  Confirm Due Date  Issue).
4.2.2 Reliability 
System Availability: Target 99.9% uptime, operating 24/7 to support student self-study, book search, and online renewals even during peak examination periods.
MTBF (Mean Time Between Failures): Core circulation operations (borrowing, returning, fine computation) must maintain an MTBF of at least 180 days without critical interruptions.
MTTR (Mean Time To Repair): Any critical service disruption (e.g., API crash or database pooler timeout) must be diagnosed and restored within 2 hours.
Data Integrity & Consistency: Database transactions for circulation records must adhere to strict ACID principles to prevent inventory count mismatches or duplicate reservation locks.
Graceful Exception Handling: All backend exceptions must be intercepted by global middleware, returning structured error responses and logging to Serilog rolling files without exposing stack traces to end users.
4.2.3 Performance
Response Time:
Standard operations (viewing book catalog, viewing news, checking profile) must load in under 2 seconds.
AI Semantic Search and RAG queries must return top matched book recommendations within 3.5 seconds.
Concurrent Throughput: The system must comfortably handle at least 100 concurrent active users without degradation in response time or database connection drops.
Catalog Capacity: Efficiently index and search a library repository of over 50,000 book titles and 200,000 physical copies using PostgreSQL indexed B-Tree and pgvector indexing.
Resource Optimization: Server CPU and RAM usage on the API container should remain below 70% under standard working loads.
4.2.4 Security
Data in Transit: Enforce HTTPS/TLS 1.3 across all communication channels between web clients, backend API, Supabase, Cloudinary, and AI endpoints.
Authentication & Authorization: Secure JWT (JSON Web Tokens) with standard claims and refresh tokens stored in HTTP-only cookies. Strict Role-Based Access Control (RBAC) separating Admin, Librarian, and Reader.
Password & Credential Protection: All user passwords must be hashed using strong one-way hashing algorithms (Argon2 / BCrypt via Supabase Auth). External API keys (Gemini, Cloudinary) must be AES-256 encrypted at rest.
Audit Trails & Logging: Critical events (reader card approvals, user deactivations, fine waivers, policy changes, book inventory write-offs) must be immutably recorded in audit tables.
Data Privacy: Personal reader information (student ID, national ID, phone, email) must be shielded from unauthorized third-party access in compliance with Vietnamese data privacy regulations.
4.2.5 Scalability
Horizontal Scaling: The ASP.NET Core API is container-ready (Docker), allowing stateless multi-instance scaling behind reverse proxies or load balancers.
Multi-Campus Expansion: The database architecture supports multi-campus filtering and location tags, allowing expansion across multiple FPT University campuses (Hanoi, Da Nang, Quy Nhon, HCMC, Can Tho) without redesign.
Cloud-First Architecture: Decoupled storage (Cloudinary for static assets, Supabase for relational data, Gemini for vector processing) ensures zero local storage bottlenecks.
